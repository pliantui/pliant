With the ask panel, a user points at part of the page and types what they want, such as "only overdue orders" or "put the overdue card first". The change shows on the page as a preview, and it's saved only when they choose **Lock in**. AI is optional: everything it can do, users can also do by hand with the controls on the page.

<Callout
  variant="warning"
  title="Not fully implemented yet"
  data-unfinished="not-implemented"
>
  Regions, forms and sidebar links don't have controls of their own yet, so
  today they change only through the ask panel. Tables can be changed by hand.
</Callout>

<Steps>

<Step>Add the server route</Step>

Install the server package, the AI SDK and a model provider:

```bash
npm install @pliantui/server ai @ai-sdk/anthropic
```

  variant="warning"
  title="Not fully implemented yet"
  data-unfinished="not-implemented"
>
  The `@pliantui/*` packages aren't on npm yet, so this install command works
  only inside the Pliant repository.
</Callout>

Add your provider's API key to `.env.local`, such as `ANTHROPIC_API_KEY`. Then add the route that answers asks:

## What the user sees

1. They turn on point mode in one of three ways: hold <Kbd>Alt</Kbd> (<Kbd>Option</Kbd> on a Mac), press <Kbd>Ctrl</Kbd> <Kbd>.</Kbd> (<Kbd>⌘</Kbd> <Kbd>.</Kbd> on a Mac), or click the point mode button. The parts they can ask about light up, and they click one. They can also open the panel and pick a part from its list.
2. They type an ask, or pick a suggestion, and press <Kbd>Enter</Kbd>. <Kbd>Shift</Kbd> <Kbd>Enter</Kbd> adds a new line.
3. The change appears on the page as a preview, with a short sentence describing it.
4. **Lock in** saves it. **Discard** drops it. Until then, nothing is saved.

If the ask is unclear, the panel asks a short question back. If it's about changing data, such as "delete these orders", it explains that it can only change how the page looks.

## What happens on your server

1. The route checks the user is signed in, and that the request is well formed.
2. Asks that clearly act on data are turned away before they reach the model.
3. The model is given a description of the target and the ask, and answers with [operations](/docs/concepts/operations), from those the target allows.
4. Every operation is checked. If any fails, the model gets one chance to correct its answer.
5. The route answers with the checked change. The browser checks it again before showing it.

The route never changes your data, and the model never sees your rows. See [What the AI sees and never sees](/docs/ai/what-the-ai-sees).

## Route options

| Option         | Default  | What it does                                                |
| -------------- | -------- | ----------------------------------------------------------- |
| `model`        | Required | Any [AI SDK](https://ai-sdk.dev) language model instance.   |
| `getUser`      | Required | Returns the user's id, or `null` to answer 401.             |
| `maxToolCalls` | 8        | Most tool calls the model may make in one answer.           |
| `timeout`      | 15000    | Milliseconds allowed for each model call.                   |
| `onError`      | None     | Called with errors the response hides, so you can log them. |

<Callout variant="warning">
  The route doesn't rate-limit asks. Keep it behind your sign-in, and add your
  own limits before you expose it. See [Costs and rate limits](/docs/ai/costs).
</Callout>

## Panel options

| Prop             | Default             | What it does                                                         |
| ---------------- | ------------------- | -------------------------------------------------------------------- |
| `endpoint`       | Required            | The URL of your ask route, such as `/api/pliant`                     |
| `targets`        | Required            | The parts users can ask about, in the order the picker lists them    |
| `target`         | None                | The id of the picked target, when you control it, as with point mode |
| `defaultTarget`  | The first target    | The target picked first, when you don't control it                   |
| `onTargetChange` | None                | Called with the id of the target the user picks                      |
| `open`           | None                | Whether the panel is open, when you control it                       |
| `defaultOpen`    | `false`             | Whether the panel starts open, when you don't control it             |
| `onOpenChange`   | None                | Called when the panel opens or closes                                |
| `placeholder`    | "Describe a change" | The prompt's placeholder                                             |
| `trigger`        | An **Ask** button   | The element that opens the panel                                     |
| `fetch`          | The global `fetch`  | Sends each ask in place of the global `fetch`                        |

`fetch` has the type of the global `fetch`. The panel calls it with `endpoint` and a `POST` request whose JSON body is the ask, then reads the answer from the response. Pass your own to add headers, to stub answers in tests, or to answer asks without a network request, as [Recordings and replay](/docs/ai/recordings#replaying-in-the-browser) shows.

## Making room for the panel

From the `sm` breakpoint up, the panel docks to the right edge; on small screens it's a sheet at the bottom. Give your page room while it's open:

```tsx
<main className="max-sm:has-[[data-slot=pliant-ask-panel]]:pb-[60dvh] sm:has-[[data-slot=pliant-ask-panel]]:pr-96">
```
