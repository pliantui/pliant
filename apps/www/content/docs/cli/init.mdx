Use the `init` command to add Pliant to a Next.js App Router project that already uses shadcn/ui.

<Callout
  variant="warning"
  title="Not fully implemented yet"
  data-unfinished="not-implemented"
>
  The `pliantui` CLI and the `@pliantui/*` packages aren't on npm yet, so the
  `npx pliantui` and `npm install` commands on this page work only inside the
  Pliant repository.
</Callout>

<Steps>

<Step>Install the React package</Step>

```bash
npm install @pliantui/react zod
```

<Step>Add the Pliant registry</Step>

Add `@pliant` to the `registries` in `components.json`, so the shadcn CLI can find Pliant's components by name:

```json title="components.json"
{
  "registries": {
    "@pliant": "https://pliantui.dev/r/{name}.json"
  }
}
```

<Step>Add the region component</Step>

```bash
npx shadcn@latest add @pliant/pliant-region
```

</Steps>

  </TabsContent>
</CodeTabs>

The command installs the `@pliantui/react` package with your package manager, found from your lockfile or, without one, the `packageManager` field in `package.json` (pnpm, npm, yarn or bun), adds the `@pliant` registry to `components.json`, and adds the `pliant-region` component to your project with `shadcn add @pliant/pliant-region`. It asks before each step and shows what it will do. If you answer no, it prints the command or the `components.json` entry so you can add it yourself.

When it's done, your project has the package in `package.json`, the registry in `components.json` and the component in your components folder:

<FileTree>
  <Folder name="components">
    <Folder name="pliant">
      <File name="pliant-region.tsx" />
    </Folder>
  </Folder>
  <File name="components.json" />
  <File name="package.json" />
</FileTree>

From then on, add any other Pliant component by name, such as `npx shadcn@latest add @pliant/pliant-data-table`. The [registry page](/docs/registry) lists them all.

```txt
Usage: pliantui init [options]

add Pliant to your Next.js and shadcn project

Options:
  -y, --yes             skip confirmation prompts. (default: false)
  -c, --cwd <cwd>       the working directory. defaults to the current
                        directory. (default: "/home/you/my-app")
  -r, --registry <url>  the registry to install components from. (default:
                        "https://pliantui.dev/r")
  -h, --help            display help for command
```

Your project needs:

- Next.js with an `app` or `src/app` folder
- a `components.json` file. If it's missing, run `npx shadcn@latest init`, then run `pliantui init` again.

Other frameworks and the Next.js Pages Router aren't supported by `init`. In these cases the command exits with an error and changes nothing.

`init` doesn't edit your pages. When it finishes, it prints the code to wrap a page with:

<include cwd lang="tsx">
  snippets/cli/init-page.tsx#page
</include>

The `surface` is the page's route pattern, such as `/orders/[id]`. `PliantRoot` and `PliantPrePaint` must receive the same `surface`. `storage={localAdapter}` keeps each user's changes in their browser. `PliantRegion` is the component `init` added: its `slots` are the parts of the page that users can rearrange, for example through the [ask panel](/docs/ai).

`PliantPrePaint` keeps a customized page from flashing its original layout before Pliant applies the user's changes.

Run `init` again at any time. It skips what is already installed, and says so when there's nothing left to do. If `components.json` already has an `@pliant` entry, `init` keeps it.

Pass `--yes` to skip the questions, for example in a script. Pass `--registry` to install the components from your own registry: `init` sets `@pliant` in `components.json` to `<url>/{name}.json`, replacing an entry that points elsewhere. The URL must use `http` or `https` and can't contain a query string, a fragment or credentials.
