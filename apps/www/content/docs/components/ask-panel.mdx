The ask panel is a chat about the page. Users open it from the [Customize menu](/docs/concepts/customize-menu) with **Ask for a change…**, describe what they want, and get a preview they can lock in or discard.

The panel is built from [AI Elements](https://ai-sdk.dev/elements), Vercel's shadcn-style chat components, which the command installs with it. The chat's code loads when the panel first opens, so it adds nothing to the page's first load in the browser. You also need a route that answers asks with `createPliantHandler` from `@pliantui/server`. See [AI](/docs/ai).

## Usage

Give the panel your ask route and the parts of the page users can ask about. Each target describes the node to the AI and offers suggestions. Render it once per page, inside `PliantRoot`; the Customize menu and [point mode](/docs/components/point-mode) open it on the part the user chose.

## What users can ask

Users ask for what they'd otherwise file a feature request for, about the part of the page they chose:

| Ask                                       | What changes                                                              |
| ----------------------------------------- | ------------------------------------------------------------------------- |
| add a card for this quarter's refund rate | A **Refund rate** card shows the share of this quarter's orders refunded. |
| show the cards in a two-column grid       | The cards sit in two columns.                                             |

The preview above offers both asks under the cards; the refund rate card, marked scripted, plays a hand-written answer. It replays recorded answers without calling a model, so an ask that isn't recorded gets a reply that lists the suggestions.

### The chat

Each ask and its answer stay in the chat. An answer that changes the page shows:

- the sentences describing the change;
- **Steps**, which name each operation it chose, such as "Chose an operation: Add column", and end with the check against the part's rules;
- **Lock in** and **Discard**, inline under the answer, while its preview shows on the page.

Nothing is saved until the user chooses **Lock in**. Once they decide, the answer says **Locked in.** or **Discarded.**, and notes any change that stays for this session only, such as the page of a table. An answer can also ask a short question back, or say why it can't make the change. Each ask is answered on its own, so a follow-up should say the whole change again.

Only one preview shows on the page at a time. If it belongs to another chat, a bar above the prompt says so, with **Lock in**, **Discard** and **Go to chat**.

### Several chats

The menu at the top of the panel lists the user's chats, titled from their first ask, and switches between them. The **New chat** button starts another. **Delete this chat** opens a confirm step, **Delete**, so a chat isn't lost to a stray click. Deleting a chat doesn't undo the changes locked in from it.

### Chats aren't saved

Chats live in memory and clear when the user leaves or reloads the page; the panel tells them so with "Chats aren't saved. They clear when you leave the page." Locked-in changes are saved as usual, so they stay.

## Rules and guardrails

- The AI never writes code or queries. It picks from the operations the target's manifest allows, and every answer is checked before it previews.
- A change previews first. Nothing is saved until the user locks it in, and discarding a preview leaves the page as it was.
- Chats are kept only in memory, so nothing about them is stored in the browser or sent to your server beyond each ask.
- The AI only sees what each target's context describes: labels, ids and field types, never your rows. See [what the AI sees](/docs/ai/what-the-ai-sees).

### Keep the panel out of the server bundle

In an app that renders on the server, the chat's code still lands in the server bundle. Load the panel only in the browser to keep it out:

```tsx title="components/ask-panel.tsx"
"use client"

import dynamic from "next/dynamic"

export const AskPanel = dynamic(
  () =>
    import("@/components/pliant/pliant-ask-panel").then(
      (module) => module.PliantAskPanel
    ),
  { ssr: false }
)
```

## Options

| Prop                                    | Type                       | Description                                                                     |
| --------------------------------------- | -------------------------- | ------------------------------------------------------------------------------- |
| `endpoint`                              | `string`                   | The URL of the route that answers asks with `createPliantHandler`.              |
| `targets`                               | `PliantAskTarget[]`        | The nodes users can ask about, in picker order.                                 |
| `target` / `defaultTarget`              | `string`                   | The picked target, controlled or uncontrolled. Defaults to the first.           |
| `onTargetChange`                        | `(target: string) => void` | Called when the user picks a target.                                            |
| `open` / `defaultOpen` / `onOpenChange` |                            | The panel's open state.                                                         |
| `placeholder`                           | `string`                   | The prompt's placeholder.                                                       |
| `trigger`                               | `ReactElement \| null`     | An element that opens the panel. Defaults to none; the Customize menu opens it. |
| `fetch`                                 | `typeof fetch`             | Sends each ask in place of the global `fetch`, as for tests.                    |

## Accessibility

- The panel is a labelled complementary landmark, and focus moves to the prompt when it opens.
- The conversation is a polite live region, so screen readers announce each new answer as it arrives. Switching chats doesn't announce the old messages again.
- The chat menu is a Radix menu, with full keyboard support. <Kbd>Enter</Kbd> sends an ask and <Kbd>Shift</Kbd> <Kbd>Enter</Kbd> adds a new line.
- On phones it docks to the bottom of the screen, and the page stays scrollable above it.
