## What users can ask

The table already sorts, hides and reorders columns from its own controls. Asks are for the changes you wouldn't build ahead of time, because each user wants something different. A user points at the table and asks:

| Ask                                                 | What changes                                                                    |
| --------------------------------------------------- | ------------------------------------------------------------------------------- |
| add a column with each order's share of total value | A **Share of value** column, calculated from Value and shown as a percent.      |
| highlight overdue orders in red                     | Rows whose status is overdue get the danger tone.                               |
| group by region and total the value                 | Rows group by region, with each region's total value and a total for the table. |
| show value by region as a bar chart                 | The table shows its data as a bar chart, with regions along the x axis.         |
| save overdue orders in the south as a preset        | An **Overdue in the south** preset joins the toolbar's presets menu.            |

Each change previews in place until the user locks it in or discards it. The preview above replays recorded asks, such as "only show overdue orders".

## Rules and guardrails

- Users change how the table shows your data, never the data itself. Sorting, filtering and grouping run on the rows you already pass in, or through your server's permissions in [server mode](/docs/data/server-mode).
- In [server mode](/docs/data/server-mode), a field a user isn't allowed to see stays out of the table, the menus and what the AI is told. See [permissions](/docs/data/permissions). In client mode, hiding a column only changes what's shown.
- Filters and calculated columns use Pliant's expression format, which can only read the fields you describe. It never runs code or SQL.

## Options

### PliantDataTable

| Prop                             | Type                              | Description                                                        |
| -------------------------------- | --------------------------------- | ------------------------------------------------------------------ |
| `table`                          | `Table`                           | The table from `useTable`, with the options from `usePliantTable`. |
| `formatAggregate`                | `(value, unit, format) => string` | Formats a group's total. Defaults to the column's format.          |
| `formatNumber`                   | `(value: number) => string`       | Formats the number of rows in a group.                             |
| `formatHighlight`                | `(highlight) => string`           | Names a highlight for screen readers.                              |
| `aria-label` / `aria-labelledby` | `string`                          | The table's accessible name. One of them is required.              |

### usePliantTable

`usePliantTable(options, { id, dataset })` takes TanStack's table options and returns them with the user's layers applied. `id` is the table's node id; `dataset` describes the fields users can filter and ask about.

## Accessibility

- It renders a real `<table>`, with sortable headers as buttons that announce their sort direction.
- Highlighted rows are named for screen readers, not only shown in colour. Pass `formatHighlight` to name them by rule, as in "Highlighted: Overdue".
- Column menus and the view options are Radix menus, with full keyboard support.
