## Usage

Render `PliantNav` in place of shadcn's `SidebarMenu`, with each link by its id. `PliantSidebarProvider` takes the place of `SidebarProvider` and saves whether the sidebar is open as the user's own default.

## What users can ask

Users point at the sidebar and ask:

| Ask                                  | What changes                            |
| ------------------------------------ | --------------------------------------- |
| open on tickets when I sign in       | Tickets becomes this user's start page. |
| fold reports and settings under More | Both links move into a **More** item.   |
| pin customers to the top             | Customers moves to the top of the list. |

The preview above replays "pin customers to the top" and "hide reports". Each link's options menu also lets users make it their start page.

## Rules and guardrails

- Users change order, visibility and their start page. They can't add links or change where a link goes.
- A hidden link only leaves the sidebar. The page is still there, and your own permissions decide who can open it.

## Options

### PliantNav

| Prop    | Type                            | Description                                               |
| ------- | ------------------------------- | --------------------------------------------------------- |
| `id`    | `string`                        | The nav's node id: kebab-case, unique within the surface. |
| `items` | `Record<string, PliantNavItem>` | Each link by its id. The key order is the base order.     |

A `PliantNavItem` has a `title`, a `url`, an optional `icon` and `isActive` for the current page.

### PliantSidebarProvider

| Prop          | Type      | Description                                         |
| ------------- | --------- | --------------------------------------------------- |
| `id`          | `string`  | The id of the nav whose open state this is.         |
| `defaultOpen` | `boolean` | Applies until the user opens or closes the sidebar. |

## Accessibility

- Wrap the nav in `<nav aria-label="...">` so screen readers list it as a landmark.
- The current page's link gets `aria-current="page"`.
- Each link keeps its own list item, so the tab order follows the order users see.
