## Installation

```bash
npm install @pliantui/react
```

`PliantRoot` ships in the package, so there's nothing to copy.

## Usage

Wrap each page, or each part of the app with its own saved layout, in a `PliantRoot`. Give it a `surface`, usually the route, and somewhere to keep the layers.

<include cwd lang="tsx">
  snippets/components/root.tsx#usage
</include>

`localAdapter` keeps each user's changes in their browser. To keep them on your server, use `serverAdapter({ endpoint })`. Create it in a client module, such as your providers file, because a Server Component can't pass an adapter object. See [storage](/docs/storage).

## What users can ask

The root doesn't change anything itself: it carries the changes users make to every component inside it, whichever part of the page they ask about.

| Ask                                       | What changes                                                              |
| ----------------------------------------- | ------------------------------------------------------------------------- |
| add a card for this quarter's refund rate | A **Refund rate** card shows the share of this quarter's orders refunded. |
| show the cards in a two-column grid       | The cards sit in two columns.                                             |

The preview above offers both asks on a region. The grid replays a recorded answer; the refund rate card, marked scripted, plays a hand-written one.

## Rules and guardrails

- Layers apply in order: your base, then team defaults, then the user's own changes. A user's change never alters a team default; it sits on top of it.
- Every change is checked against the components' manifests and your rules before it applies. A change that would break a rule is skipped, and the rest still applies.
- Changes are saved per surface, so two pages with the same component ids keep separate layouts.

## Options

| Prop        | Type                                     | Description                                                                                                                                             |
| ----------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `surface`   | `string`                                 | The surface the layers belong to: a route pattern or a surface id.                                                                                      |
| `storage`   | `StorageAdapter \| () => StorageAdapter` | Where the layers are loaded from and personal changes saved to, such as `localAdapter` or `serverAdapter(options)`. Read once, when the surface mounts. |
| `layers`    | `StoredLayers`                           | The layers, loaded on the server, so the first render shows them.                                                                                       |
| `teamOrder` | `string[]`                               | Team ids, highest precedence first.                                                                                                                     |
| `lang`      | `string`                                 | The UI language as a BCP 47 tag. Defaults to the page's `<html lang>`.                                                                                  |
| `messages`  | `Partial<PliantMessages>`                | Text to show in place of the English defaults.                                                                                                          |
| `inventory` | `PliantInventory`                        | The nodes `pliantui scan` found on the surface, checked in development.                                                                                 |
| `onError`   | `(error: unknown) => void`               | Called when saving or loading fails. Defaults to `console.error`.                                                                                       |

## Accessibility

- The root renders no markup of its own, so it doesn't change your page's structure.
- Status changes, like a saved change, are announced by the components that show them.
