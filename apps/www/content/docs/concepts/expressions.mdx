---
title: Expressions and functions
description: How calculated columns, totals and highlights are written as small JSON trees over a fixed list of typed functions.
---

Some changes carry a calculation: a calculated column such as each order's share of revenue, a total for each group, or the condition that highlights a row. Pliant writes these as **expressions**: small JSON trees built from a fixed list of functions. Pliant evaluates them itself, so an expression can't run code, and it can be stored and checked like the rest of a change.

This expression is true for orders over ₹100,000:

```json
{ "fn": "gt", "args": [{ "field": "value" }, { "value": 100000 }] }
```

And this change uses it to highlight those rows in the orders table:

```json
{
  "op": "addHighlight",
  "target": "orders-table",
  "id": "large-orders",
  "when": {
    "fn": "gt",
    "args": [{ "field": "value" }, { "value": 100000 }]
  },
  "tone": "emphasis"
}
```

To compute expressions, a table needs to know each field's type. Pass `usePliantTable` a `dataset` option: an object with the table's `fields`, each with its `type`, and its `timeZone`. Without it, the table shows no calculated columns, totals or highlights.

## The four kinds of node

| Node                        | Meaning                                         |
| --------------------------- | ----------------------------------------------- |
| `{ "field": "value" }`      | A field of the row.                             |
| `{ "value": 100000 }`       | A literal: a string, number, boolean or `null`. |
| `{ "ref": "share" }`        | A calculated column or total, by its id.        |
| `{ "fn": "…", "args": [] }` | A function call.                                |

An expression has at most 8 levels of nesting, 16 arguments per function and 128 nodes in all.

## Where expressions are used

- **`addDerived`** adds a calculated column, with a value for every row. It can use window functions: functions such as `share` or `rank` that compare a row with the other rows in its group.
- **`addAggregate`** adds a total for each group of rows, and for the table as a whole. It reads fields only inside functions such as `sum` and `mean`.
- **`addHighlight`** gives rows a tone (`emphasis`, `success`, `warning` or `danger`) when its condition is true.

This calculated column shows each order's share of the total value:

```json
{
  "op": "addDerived",
  "target": "orders-table",
  "id": "share",
  "label": "Share of value",
  "expr": { "fn": "share", "args": [{ "field": "value" }] }
}
```

And this total shows the average order value for each group:

```json
{
  "op": "addAggregate",
  "target": "orders-table",
  "id": "average-value",
  "label": "Average order",
  "expr": { "fn": "mean", "args": [{ "field": "value" }] }
}
```

## Types and units

Every function declares the types of its arguments and its result: `number`, `integer`, `string`, `boolean`, `date` or `datetime`. Pliant checks an expression against your dataset's fields before computing it, and skips one that doesn't fit.

Numbers can carry a unit, such as a currency or a percent, and units follow arithmetic. Adding two rupee amounts gives rupees; adding rupees to dollars fails the check. Dividing rupees by rupees gives a plain number, and `share` returns a percent.

## Missing values

Most functions return `null` when an argument is `null`, as SQL does. Totals such as `sum` and `mean` skip `null` values. Dividing by zero gives `null`, never an error. `coalesce` picks its first argument that isn't `null`, and `isNull` tests for one.

## Functions

The catalog has 65 functions. A **row** function reads one row, an **aggregate** function reads every row of a group, and a **window** function gives each row a value computed over its group, or over all rows that pass the filters when the table isn't grouped.

| Group      | Functions                                                                                                                                                                    |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Arithmetic | `add`, `sub`, `mul`, `div`, `abs`, `round`, `floor`, `ceil`, `min2`, `max2`, `clamp`, `percentChange`                                                                        |
| Logic      | `if`, `and`, `or`, `not`, `eq`, `eqI`, `neq`, `gt`, `gte`, `lt`, `lte`, `between`, `in`, `isNull`, `coalesce`                                                                |
| Text       | `concat`, `lower`, `upper`, `length`, `contains`, `containsI`, `startsWith`, `startsWithI`, `left`, `right`                                                                  |
| Date       | `dateDiff`, `datePart`, `dateTrunc`, `addDays`, `today`, `age`                                                                                                               |
| Aggregate  | `count`, `countIf`, `sum`, `sumIf`, `mean`, `min`, `max`, `variance`, `stddev`, `variancePop`, `stddevPop`, `median`, `percentile`, `mode`, `distinctCount`, `first`, `last` |
| Window     | `rank`, `denseRank`, `runningSum`, `share`, `zScore`                                                                                                                         |

Functions ending in `I`, such as `containsI`, ignore case. `today` is the viewer's date for personal changes, and the dataset's time zone for team and organization defaults.

Each function's exact arguments, result, unit and handling of `null` are in `functionCatalog`, exported by `@pliantui/contract` and published as `schema/functions.json`.

## Filters aren't expressions

A filter is simpler: a field, an operator and a value.

```json
{
  "op": "setFilter",
  "target": "orders-table",
  "filter": {
    "field": "status",
    "operator": "in",
    "value": ["overdue", "pending"]
  }
}
```

The operators are `eq`, `neq`, `in`, `contains`, `startsWith`, `gt`, `gte`, `lt`, `lte`, `between`, `isNull` and `custom`. `contains` and `startsWith` ignore case, as most search boxes do. A missing value passes only `isNull`.
