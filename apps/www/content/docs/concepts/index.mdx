title: Core concepts
description: The pieces Pliant is built from, such as surfaces, addresses, regions and overlays.
---

Pliant is built from a few pieces: surfaces, the nodes and items on them, and overlays that change those nodes. This page covers each one.

## Surfaces

A surface is the scope that overlays belong to. Every overlay names one surface, and Pliant loads and resolves a surface's overlays together.

A surface is one of:

- **A route pattern**, such as `/orders` or `/orders/[id]`. Use the pattern, not the URL, so one customization applies to every order page. Catch-all segments (`[...slug]`, `[[...slug]]`) work too. Characters outside ASCII must be percent-encoded as UTF-8, with uppercase hex.
- **A kebab-case id**, such as `app-shell`, for parts of the app that aren't tied to one route.
- **`@app`**, which is reserved. Pliant resolves `@app` overlays together with each surface's overlays; your storage adapter returns them with each surface's layers. The default `localAdapter()` doesn't.

## Addresses

Everything an overlay changes has an address.

A **node** is a part of the page users can change, such as a region or a table. Its id is kebab-case, starts with a letter and is at most 64 characters long. Node ids must be unique across a surface.

A node can have **collections**: named lists of items. There are five: `slots`, `columns`, `fields`, `items` and `actions`. An item's address is its node's address, the collection and the item's id:

| Address                      | What it names                     |
| ---------------------------- | --------------------------------- |
| `key-metrics`                | The region `key-metrics`          |
| `key-metrics/slots/revenue`  | The `revenue` slot in that region |
| `orders-table`               | The table `orders-table`          |
| `orders-table/columns/notes` | The `notes` column of that table  |

Slot ids are kebab-case. Ids in the other collections can also contain uppercase letters and `_`, so TanStack column ids such as `createdAt` work as they are. No id contains a dot, and every id starts with a letter.

`dashboard/slots/revenue` and `revenue` address the same node. A node keeps its identity when an overlay moves it to another place, so changes to it follow it.

## Regions and slots

A region is a node with an ordered `slots` collection. You give `PliantRegion` an `id` and a `slots` object, and the order of the object's keys is the base order. The region never looks inside a slot's content, so a slot can hold anything: a host element, a client component or a Server Component.

Overlays can reorder a region's slots, hide them, pin them to the start or end, fold some of them behind a disclosure button, labelled "More" unless the overlay gives it a label, lay the region out as a stack, a row or a grid of up to four columns, set how many columns a slot spans, and group slots into a new wrapper with its own layout. Layout changes are set per breakpoint. Without one, they apply from `md` up, and below `md` the region keeps the classes you gave it.

A hidden slot stays mounted with React's `Activity`, so its state survives being hidden and shown again. Its content still reaches the browser.

Tables use the same addresses, with their columns as the `columns` collection: `orders-table/columns/notes`. Columns can be hidden, reordered, pinned and resized, and tables can be sorted, filtered, grouped and paged.

## Overlays

An overlay is a JSON document that holds a list of operations for one surface and one layer:

```json title="overlay.json"
{
  "v": 1,
  "id": "01JD5Z8Q9W3X4Y5Z6A7B8C9D0E",
  "surface": "/orders",
  "layer": "personal",
  "ops": [
    {
      "op": "setSort",
      "target": "orders-table",
      "sort": [{ "field": "value", "dir": "desc" }]
    },
    { "op": "hide", "target": "orders-table/columns/notes" }
  ],
  "basis": { "contract": 1, "core": "0.0.0", "manifests": {} },
  "source": "manual",
  "createdBy": "user_123",
  "createdAt": "2026-11-20T09:30:00Z"
}
```

| Field       | Description                                                                                                                                                                                                                                   |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `v`         | The format version, always `1`.                                                                                                                                                                                                               |
| `id`        | A [ULID](https://github.com/ulid/spec). Saving an overlay with the same `id` replaces it.                                                                                                                                                     |
| `surface`   | The surface it applies to.                                                                                                                                                                                                                    |
| `layer`     | `org`, `team`, `personal` or `session`.                                                                                                                                                                                                       |
| `scope`     | Who the overlay is for: `{ "org": "…" }` on the `org` layer, `{ "team": "…" }` (optionally with `org`) on the `team` layer, and none otherwise.                                                                                               |
| `ops`       | Between 1 and 500 [operations](/docs/concepts/operations).                                                                                                                                                                                    |
| `basis`     | What the overlay was made against: the contract version, the `@pliantui/core` version, the version of each component manifest it used, and optionally the version of each dataset and of the `org` and `team` overlays it was made on top of. |
| `source`    | How it was made: `ai`, `manual`, `chip`, `share` or `promote`.                                                                                                                                                                                |
| `lang`      | Optional. The BCP 47 language tag of its labels, such as `en-US`.                                                                                                                                                                             |
| `explain`   | Optional. One short sentence per op, describing the change to the user.                                                                                                                                                                       |
| `createdBy` | Who made it.                                                                                                                                                                                                                                  |
| `createdAt` | When it was made, as an RFC 3339 timestamp with seconds.                                                                                                                                                                                      |

An overlay keeps fields it doesn't recognize, so an overlay written by a newer version of Pliant loads and saves again without losing anything.

The overlay's JSON Schema is published at [`https://pliantui.dev/schema/overlay.json`](https://pliantui.dev/schema/overlay.json), for tools and for implementations in other languages.

Overlays live in layers, from organization-wide defaults down to a single browser tab. See [Layers](/docs/concepts/layers) for how they stack.
