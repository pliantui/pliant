---
title: Layers
description: How org, team, personal and session overlays stack, and which one wins.
---

Overlays live in four layers. Your page as you wrote it is the base, and the layers stack on top of it, from lowest to highest precedence:

1. **`org`**: defaults for everyone in an organization.
2. **`team`**: defaults for a team.
3. **`personal`**: one user's own changes.
4. **`session`**: changes that last for one browser tab, such as an ask panel preview that isn't saved yet, the current page of a table, and its filters, unless you save them with `persistFilters`.

Pliant loads `org` and `team` overlays from your storage adapter. Users create `personal` and `session` overlays, by using the page and through the ask panel.

## Precedence is per property

Every operation writes one or more properties of a node or item. `hide` and `show` write a column's `visible`, `move` and `pin` write its placement, and `setSort` writes the table's `sort`. When two layers write the same property, the higher layer wins. Different properties never conflict.

So if the team layer sorts `orders-table` by `value` and a user hides its `notes` column, both apply. If the user then sorts by `date`, their sort replaces the team's, because both write the same property. `setSort` and `setGroupBy` replace the whole list: sorts don't merge field by field.

Some properties are keyed, so they combine:

- Filters are per field. A team filter on `status` and a personal filter on `region` both apply.
- Layout and span are per breakpoint. Ops from the same scope merge breakpoint by breakpoint. When another scope, such as a higher layer, sets any breakpoint, it replaces every breakpoint set below it.

`move` anchors (`before` and `after` another item) resolve against the full order, hidden items included, so hiding an item never breaks another layer's move.

## Order within a layer

A layer can hold many overlays. They apply in a fixed order, and the later one wins:

- In the `team` layer, by the `teamOrder` you pass to `PliantRoot` (highest precedence first; teams you don't list rank below the ones you do), then by team id.
- In the `org` layer, by org id.
- Then, in every layer, by `createdAt`, then by `id`.

Within one overlay, later operations win over earlier ones. The order never depends on the order your storage returns overlays in.

If two overlays share an `id`, the first in this order is used and the others are skipped. If they tie on every key of the order but differ in content, all of them are skipped.

## Removing only undoes your own scope

`remove` deletes a node that was added with `insert` or `wrap`, but only if the same scope added it: the same team or org, or, for `personal` and `session`, the same layer. A user can hide a team's wrapper, but can't delete it from the team layer. A `remove` aimed at something another scope added doesn't apply, and it is never turned into a `hide`.
