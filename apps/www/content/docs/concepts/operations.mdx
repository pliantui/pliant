Every change a user makes is an **operation**, or op: a small JSON object with the op's name, the address it changes, and its arguments. This page explains the list of ops, what renders, and how Pliant checks each one.

```json
{ "op": "pin", "target": "orders-table/columns/customer", "where": "start" }
```

This op pins the customer column to the start of the orders table.

## A closed catalog

There are 39 ops, and the list is closed. An overlay can't contain code, CSS or markup, only ops from the catalog, each with arguments of a fixed shape. Labels are plain text, filter values are data, and calculations are [expressions](/docs/concepts/expressions) built from a fixed list of functions. That's what makes an overlay safe to store, share and accept from an AI model.

Each op belongs to a **capability**: a kind of change a component allows. A region allows `slots` and `layout`; a table allows `data`.

| Capability     | Ops                                                                  |
| -------------- | -------------------------------------------------------------------- |
| `props`        | `setProp`                                                            |
| `label`        | `rename`                                                             |
| `hideable`     | `hide`, `show`                                                       |
| `slots`        | `move`, `pin`, `collapse`                                            |
| `layout`       | `setLayout`, `span`                                                  |
| `insertable`   | `insert`, `wrap`, `remove`                                           |
| `form`         | `setDefault` on a form field                                         |
| `defaults`     | `setDefault` on one of a node's default-state props                  |
| `presentation` | `setPresentation`, `setSize`                                         |
| `nav`          | `setLanding`                                                         |
| `actions`      | `promote`, `demote`, `bindShortcut`                                  |
| `data`         | The data ops below                                                   |
| none           | `setDensity` on `@surface`; `setTextScale` and `setMotion` on `@app` |

The `data` capability covers tables and other views of data:

- `setSort`, `setFilter`, `clearFilter`, `setPage`, `setGroupBy` and `setColumnWidth`
- `addDerived`, `addAggregate`, `addHighlight`, `addSortOption`, `addFilterControl`, `addPreset` and `removeUserItem`
- `formatField`, `setViewKind`, `configureChart` and `configureStat`

The catalog is part of `@pliantui/contract`, as `opCatalog` and `schema/catalog.json`. Each entry lists the op's capability, the layers it's allowed in and its arguments. Every op is allowed in every layer except `setPage`, which is `session` only, so a page number is never saved.

## What renders

Pliant's components show the effect of these ops:

| Component                   | Ops it renders                                                                                                                                                                  |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tables (`usePliantTable`)   | `setSort`, `setFilter`, `clearFilter`, `setGroupBy`, `setPage`, `setColumnWidth`, `addDerived`, `addAggregate`, `addHighlight`, and `hide`, `show`, `move` and `pin` on columns |
| `pliant-data-table-toolbar` | `addFilterControl`, `addSortOption`, `addPreset`                                                                                                                                |
| `PliantRegion`              | `hide`, `show`, `move`, `pin`, `collapse`, `setLayout`, `span`, `wrap`, `remove`                                                                                                |
| `pliant-form`               | `hide`, `show`, `move`, `pin`, `collapse`, `setDefault` on fields                                                                                                               |
| `pliant-nav`                | `hide`, `show`, `move`, `pin`, `collapse`, `setLanding`, `setDefault` for the open state                                                                                        |

Overlays with the other ops load, save and stack like any other, but Pliant's components don't show their effect.

The [ask panel](/docs/ai) offers the model `setSort`, `setFilter`, `clearFilter`, `hide`, `show`, `move`, `pin`, `setColumnWidth` and `setLayout`, limited to the capabilities of the part the user pointed at.

## How an op is checked

Pliant checks every op on its own, and gives it one of four statuses:

| Status    | Meaning                                                                  |
| --------- | ------------------------------------------------------------------------ |
| `valid`   | It matches its shape and is allowed in its overlay's layer.              |
| `newer`   | It has arguments from a newer version of Pliant. It's kept, not applied. |
| `unknown` | Its name isn't in the catalog.                                           |
| `invalid` | Anything else.                                                           |

A saved overlay is never thrown away because of one bad op. Pliant applies the `valid` ops and skips the rest, and keeps every op when the overlay is saved again. An overlay from a newer version survives a round trip through an older one.

Answers from the ask panel are stricter: an answer is accepted only if every op in it is valid.

## Targets

Ops on an item, such as `hide` on a column, target the item's address. Ops on a whole node, such as `setSort` or `setLayout`, target the node:

```json
{
  "op": "setLayout",
  "target": "key-metrics",
  "mode": "grid",
  "columns": 2,
  "at": "md"
}
```

`move` places an item relative to another, so the move keeps working when you add cards to your page:

```json
{
  "op": "move",
  "target": "key-metrics/slots/overdue",
  "to": { "before": "revenue" }
}
```

## Limits

The catalog sets fixed limits, so no overlay can grow without bound:

- 500 ops per overlay
- 8 sort fields and 4 group-by fields
- 100 values in an `in` filter
- 4 layout columns
- 80-character labels, 64-character ids, and 256-character addresses and surfaces
- Column widths from 16 to 2000 pixels, within the column's own minimum and maximum

The JSON Schema for one op is published at <SiteUrl path="/schema/op.json" />.
