If your orders are in SQLite, including Turso and Cloudflare D1, `compileSqliteQuery` turns a table's request into one parameterized query with the user's scope, sort, filters and page, ready for `better-sqlite3`, libSQL or D1's `prepare`, and a second `count` query for the total.

```ts title="app/api/orders/rows/route.ts"
import { authorizeDataset } from "@pliantui/server/data"
import { compileSqliteQuery } from "@pliantui/server/sqlite"

import { ordersDataset } from "@/lib/datasets/orders"
import { getSessionUser } from "@/lib/session"
import { db } from "@/lib/sqlite"

export async function POST(request: Request) {
  const user = getSessionUser(request)
  if (!user) return new Response(null, { status: 401 })

  const grant = authorizeDataset(ordersDataset, user)
  if (!grant) return new Response(null, { status: 403 })

  const query = await request.json()
  try {
    const compiled = compileSqliteQuery(ordersDataset, grant, query, {
      table: "orders",
    })
    const rows = db.prepare(compiled.text).all(...compiled.values)
    const total = db.prepare(compiled.count.text).get(...compiled.count.values)
    return Response.json({ rows, rowCount: total.count })
  } catch (error) {
    if (error instanceof TypeError) {
      return Response.json({ message: error.message }, { status: 400 })
    }
    throw error
  }
}
```

The route matches the one in [server mode](/docs/data/server-mode): sign-in, the user's grant, then one page of rows with the total count, so pagination knows how many pages there are. The request is checked as `compileQuery` checks it, and a bad one throws a `TypeError`, which the route answers with a 400.

## Notes

- SQLite has no date type. Store dates as `YYYY-MM-DD` text and datetimes as ISO 8601 text with an offset.
- `median` and `percentile` totals are computed approximately, because SQLite has no percentile functions.
- On D1, each page is one `prepare(...).bind(...).all()` call, so it counts as one query against your limits.
