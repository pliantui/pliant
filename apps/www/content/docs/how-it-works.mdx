Pliant keeps the page you wrote as the base, stores each change as a small piece of data, and stacks those changes on top to show each user their own version. This page explains each part and what AI does and doesn't do.

## 1. Your page is the base

You build the page as usual, with your own components. You mark the parts users may change: a table through `usePliantTable`, and a group of cards through `PliantRegion`. Each gets an id, such as `orders-table` or `key-metrics`.

The page as a whole is a **surface**, named by its route, such as `/orders`. Everything a user changes on it is kept together.

## 2. A change is a small piece of data

When a user sorts the table by value, Pliant records that as an **operation**:

```json
{
  "op": "setSort",
  "target": "orders-table",
  "sort": [{ "field": "value", "dir": "desc" }]
}
```

Operations come from a fixed list of 39, such as `hide`, `move`, `setSort` and `setLayout`. None of them contains code, so a change can only rearrange and reshape what you built. A group of operations saved together is an **overlay**.

## 3. Changes stack in layers

Overlays live in four **layers**, from lowest to highest:

| Layer      | Who it's for                           |
| ---------- | -------------------------------------- |
| `org`      | Everyone in an organization            |
| `team`     | Everyone on a team                     |
| `personal` | One user, on every visit               |
| `session`  | One user, until the browser tab closes |

When two layers change the same thing, the higher one wins. That's decided for each property, not for the whole page: a team can set the default sort while a user hides a column, and both apply.

## 4. Each user sees the result

On every visit, Pliant loads the surface's overlays from your storage, applies them to your page and renders the result. Your components render as usual, just reordered, hidden or sorted the way the user chose.

With no overlays, the page renders exactly as you wrote it. Clearing a user's changes always brings back your page.

## 5. Where changes are kept

You choose the storage:

- **In the browser**, with `localAdapter`. Nothing to set up.
- **On your server**, with `serverAdapter` and a route you add. Changes follow users across devices, and you can serve team and organization defaults.

See [Storage](/docs/storage).

## What AI does

AI is optional. With the [ask panel](/docs/ask-panel), a user points at part of the page and describes a change, such as "put overdue orders first".

- Your server sends the model a description of that part: its id, the names of its columns or cards, and the kinds of change it allows. Never your rows.
- The model answers with operations, from the same fixed list.
- Your server checks every operation, and the browser checks it again.
- The change shows as a preview. It's saved only when the user locks it in.

## What AI doesn't do

- It doesn't write or run code, CSS or queries.
- It never sees your rows.
- It can't change your data. Asks such as "delete these orders" are turned away.
- It can't step outside the guardrails. Its changes are operations like any other, checked by the same rules.
