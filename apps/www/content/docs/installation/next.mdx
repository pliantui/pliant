## Before you start

You need a Next.js app that uses the App Router, React 19.2 or later, and [shadcn/ui](https://ui.shadcn.com/docs/installation/next) with Tailwind CSS v4. If you don't have one, follow shadcn's Next.js guide first.

## Install

### Add the package

```bash
pnpm add @pliantui/react zod
```

`@pliantui/react` is the runtime: it loads each user's changes, applies them and saves new ones.

### Add the region component

```bash
pnpm dlx shadcn@latest add https://pliantui.dev/r/pliant-region.json
```

This copies `pliant-region.tsx` into `components/pliant`, and adds the shadcn `button` if you don't have it. The file is yours to edit, like any shadcn component.

## Make a page customizable

### Wrap the page in PliantRoot

`PliantRoot` holds the changes for one surface. Give it the page's route as its `surface`.

```tsx title="app/orders/page.tsx"
import { PliantRoot } from "@pliantui/react"

export default function OrdersPage() {
  return (
    <PliantRoot surface="/orders">
      {/* your page */}
    </PliantRoot>
  )
}
```

By default, each user's changes are saved in their browser's `localStorage`. To save them to your backend instead, see [Storage](#storage).

### Make a region editable

Replace the element that holds a group of items, such as a row of cards, with `PliantRegion`. Pass each item in `slots`, keyed by an id.

```tsx title="app/orders/page.tsx"
import { PliantRoot } from "@pliantui/react"

import { PliantRegion } from "@/components/pliant/pliant-region"
import { StatCard } from "@/components/stat-card"

export default function OrdersPage() {
  return (
    <PliantRoot surface="/orders">
      <PliantRegion
        id="key-metrics"
        slots={{
          revenue: <StatCard label="Revenue" value="$48,210" />,
          orders: <StatCard label="Orders" value="1,204" />,
          overdue: <StatCard label="Overdue" value="17" />,
        }}
        className="grid grid-cols-1 gap-4 md:grid-cols-3"
      />
    </PliantRoot>
  )
}
```

The order of the keys is the default order. Ids are kebab-case and start with a letter. Overlays can now reorder, hide, resize, wrap and collapse these cards. With no overlays, the region renders the cards in the order you wrote them.

Give the region its spacing with `gap-*` classes. Each slot sits in a `display: contents` wrapper, so `space-*` and `divide-*` won't work.

### Make a table remember its sort

Pliant works with tables built on [TanStack Table](https://tanstack.com/table) v9, such as shadcn's data table. Install it if you haven't:

```bash
pnpm add @tanstack/react-table
```

Then pass your table's options through `usePliantTable` before they reach `useTable`, with an id for the table.

```tsx title="components/orders-table.tsx"
"use client"

import {
  createSortedRowModel,
  rowSortingFeature,
  sortFn_alphanumeric,
  tableFeatures,
  useTable,
} from "@tanstack/react-table"
import { usePliantTable } from "@pliantui/react/table"

const features = tableFeatures({
  rowSortingFeature,
  sortedRowModel: createSortedRowModel(),
  sortFns: { alphanumeric: sortFn_alphanumeric },
})

export function OrdersTable({ data }: { data: Order[] }) {
  const table = useTable(
    usePliantTable({ features, data, columns }, { id: "orders-table" })
  )

  // Render the table as before.
}
```

Render the table inside `PliantRoot`. When a user sorts it, the sort is saved to their personal layer and comes back after a reload. Column order, visibility, widths and pinning are saved the same way. Pagination and filters last for the browser tab only. To save filters too, pass `persistFilters: true` next to `id`.

## Storage

`PliantRoot` reads and writes through a storage adapter. The default, `localAdapter()`, keeps personal changes in `localStorage`, one key per surface. To keep them on your server, pass your own adapter to `storage`. It has two methods:

```ts title="lib/pliant-storage.ts"
import type { StorageAdapter } from "@pliantui/react"

export const pliantStorage: StorageAdapter = {
  async load(surface) {
    const response = await fetch(
      `/api/layers?surface=${encodeURIComponent(surface)}`
    )
    return response.json() // { org?: [...], team?: [...], personal?: [...] }
  },
  async save(surface, overlay) {
    await fetch(`/api/layers?surface=${encodeURIComponent(surface)}`, {
      method: "PUT",
      body: JSON.stringify(overlay),
      keepalive: true,
    })
  },
}
```

- `load` returns the surface's saved overlays by layer. Pliant validates each one and skips any that don't load.
- `save` stores one personal overlay, replacing a saved overlay with the same `id`. Pliant also saves while the page unloads, which is why the request uses `keepalive`.

Pass the adapter from a client component, since an object of functions can't be passed from a Server Component.

<Callout title="Coming before 1.0">
  The storage adapter interface will change before 1.0, to support saving team
  and org overlays and safe concurrent saves. The `org` and `team` layers
  already load from your adapter, but there is no UI for creating them yet.
</Callout>

## Add the ask panel

This step is optional. Pliant works without AI.

The ask panel lets users describe a change, such as "hide the overdue card". It shows the result on the page as a preview. Nothing is saved until the user locks it in.

### Add the server route

```bash
pnpm add @pliantui/server ai @ai-sdk/anthropic
```

```ts title="app/api/pliant/route.ts"
import { anthropic } from "@ai-sdk/anthropic"
import { createPliantHandler } from "@pliantui/server"

export const POST = createPliantHandler({
  model: anthropic("claude-haiku-5-5"),
  getUser: async (request) => (await auth(request))?.userId ?? null,
})
```

The route turns a request into a validated overlay and sends it back. It never changes your data. `model` takes any [AI SDK](https://ai-sdk.dev) model. `getUser` returns the signed-in user's id, or `null` to answer with a 401.

<Callout type="warn">
  The route has no rate limits yet. Keep it behind your sign-in before you
  expose it.
</Callout>

### Add the panel

```bash
pnpm dlx shadcn@latest add https://pliantui.dev/r/pliant-ask-panel.json
```

Render it inside `PliantRoot`, with the route's URL and the regions users can ask about:

```tsx title="components/ask-button.tsx"
"use client"

import {
  PliantAskPanel,
  type PliantAskTarget,
} from "@/components/pliant/pliant-ask-panel"

const targets = [
  {
    id: "key-metrics",
    label: "Key metrics",
    context: {
      manifest: {
        kind: "region",
        version: 1,
        description: "A row of key metric cards",
        capabilities: { slots: true, hideable: true, layout: true },
      },
      collection: {
        name: "slots",
        items: [
          { id: "revenue", label: "Revenue" },
          { id: "orders", label: "Orders" },
          { id: "overdue", label: "Overdue" },
        ],
      },
    },
  },
] satisfies PliantAskTarget[]

export function AskButton() {
  return <PliantAskPanel endpoint="/api/pliant" targets={targets} />
}
```

`context` tells the model what the region holds: its kind, what can change, and its items. It never includes your rows. For now, you write each target's `context` by hand.

The panel opens from an "Ask" button and docks to the right edge of the screen. Add padding to your layout while it's open, such as `sm:has-[[data-slot=pliant-ask-panel]]:pr-96`, so it doesn't cover the page.

## See it working

The repository has a complete example: an orders page with a region of metric cards, a data table and the ask panel.

```bash
git clone https://github.com/pliantui/pliant.git
cd pliant
pnpm install
pnpm build:packages
PLIANT_ASK_ENABLED=1 pnpm --filter www dev
```

Open [localhost:4000/examples/orders](http://localhost:4000/examples/orders). Sort the table, hide a column and reload: the changes stay. The ask panel replays recorded answers, so it only answers its suggested asks and needs no API key.
