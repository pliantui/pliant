---
title: Expression rules
description: The exact rules for expressions and filters, covering node limits, types, units, nulls, string comparison, dates and display order.
---

Calculated columns, totals and highlights are written as [expressions](/docs/concepts/expressions): JSON trees over a fixed list of functions. This page gives the exact rules. Each function is listed in the [function reference](/docs/reference/functions).

## Nodes and limits

| Node                        | Meaning                                        |
| --------------------------- | ---------------------------------------------- |
| `{ "field": "price" }`      | A field of the row                             |
| `{ "value": 0.2 }`          | A literal: a string, number, boolean or `null` |
| `{ "ref": "margin" }`       | Another calculated column or total, by its id  |
| `{ "fn": "…", "args": [] }` | A function call                                |

An expression has at most 8 levels of nesting, 16 arguments per function and 128 nodes. Field ids can't contain dots, so `customer.region` is rejected.

## Row and aggregate expressions

- `addDerived` takes a **row** expression. It may use window functions, which give a row a value over its partition. A column with window functions can't be filtered or grouped by.
- `addAggregate` takes an **aggregate** expression: it reads fields only inside aggregate functions such as `sum`.
- `addHighlight` takes a row expression that must be true or false. It may use window functions and `ref` calculated columns. A row with several highlights lists them in the order their operations applied, and the data table shows the tone of the last one.

The arguments of aggregate and window functions are row expressions, so they can't contain other aggregate or window functions. Row functions can combine aggregates, as in `div(sum(a), sum(b))`.

A window function's **partition** is the row's group when the table is grouped, and otherwise every row that passes the filters.

## Types

Every function declares the types of its arguments and its result: `number`, `integer`, `string`, `boolean`, `date` or `datetime`. An integer is accepted wherever a number is. Integer fields are `integer`; number, currency and percent fields are `number`; string, text, enum, id, url and email fields are `string`.

Arguments joined by "same as" form a group, and their types unify: `integer` with `number` gives `number`, `date` with `datetime` gives `datetime`, and a `null` literal fits any type.

A string literal fits a `date` as `YYYY-MM-DD`, and a `datetime` as an ISO 8601 date-time with seconds, optional milliseconds, and `Z` or an offset.

`checkExpression` from `@pliantui/core` checks an expression against a dataset's fields and returns its type, or an error that names the problem. A table skips an expression that doesn't check.

## Units

A number's unit comes from its field (its currency, `percent`, or a unit declared on the field), or is `percent` for functions such as `percentChange` and `share`. Literals and other numbers have none. A value without a unit fits any unit. Formats never change units.

- Arguments in a group must share a unit, so adding rupees to dollars fails the check.
- In a product, a factor without a unit takes the other's unit, a percent of a unit is that unit, and a percent of a percent is a percent. Two other units fail the check.
- In a quotient, dividing by the dividend's own unit gives no unit. Dividing by a number without a unit, or by a percent, keeps the dividend's unit. Any other divisor with a unit fails the check.

## Nulls

- Most row functions propagate `null`: if an argument is `null`, the result is `null`.
- Aggregate and window functions skip `null` values. `sum` of no values is `0`, and `mean`, `min` and `max` of no values are `null`. A window function gives `null` for a row whose value is `null`.
- `if` picks `else` when its condition is `null`.
- `and` is `false` when any argument is `false`, even if others are `null`, and `or` is `true` when any argument is `true`. Otherwise either is `null` when an argument is.
- `coalesce` returns its first argument that isn't `null`, and `isNull` is never `null`.
- `in` is `null` when its first argument is, and a `null` in its list never matches.
- `concat` treats `null` as an empty string and is never `null`.

A value that isn't a finite number (`NaN` or infinity), read or computed, is `null`. `div` by zero and `percentChange` from zero are `null`.

## Numbers

Numbers are IEEE 754 doubles, currency included, and calculations use the full value. A currency value is displayed rounded to its format's decimals, or to its currency's minor units (2 for USD, 0 for JPY).

## Strings

- Functions compare strings by Unicode code point, case included. Lengths and positions count code points. Sorting a table with `setSort` is separate and uses locale-aware collation.
- `eqI`, `containsI` and `startsWithI` ignore case. They lowercase both strings as `lower` does, without locale-specific rules, then compare as `eq`, `contains` and `startsWith` do. Lowercasing isn't full case folding: `containsI("Straße", "SS")` is `false`, and `eqI("ΟΔΟΣ", "οδοσ")` is `false` because a final `Σ` lowercases to `ς`.

## Dates and time zones

Dates and datetimes are read in the dataset's time zone, with millisecond precision. A date compared with a datetime is the start of that day there.

`today` is the viewer's date for `personal` and `session` overlays, and the date in the dataset's time zone for `org` and `team` overlays.

## Display order

`first`, `last` and `runningSum` read rows in display order: the table's sort, with ties and an unsorted table in ascending order of the row key. Number keys come first, in numeric order, so `2` comes before `10`; other keys compare by the code points of their text. TanStack Table's `getRowId` returns text, so its keys compare as text.

Every dataset has a row key: the table's `getRowId`, or else its field named `id`. A table whose dataset has neither fails to load with an error. A sort by a window column is left out when computing window functions, since its values depend on that order.

## Filters

A filter is a field, an operator and a value, not an expression:

```json
{
  "op": "setFilter",
  "target": "orders-table",
  "filter": { "field": "value", "operator": "between", "value": [100, 500] }
}
```

The operators are `eq`, `neq`, `in`, `contains`, `startsWith`, `gt`, `gte`, `lt`, `lte`, `between`, `isNull` and `custom`. An `in` list holds 1 to 100 values, `between` takes two and includes both ends, and `isNull` takes none.

- A missing value passes only `isNull`. `neq` and every comparison leave it out, as in SQL.
- `eq`, `neq` and `in` compare text case-sensitively. `contains` and `startsWith` ignore case, lowercasing both sides as `containsI` does.
- A number compares with a number or numeric text, and two pieces of text compare as text. Values that can't be compared, such as a word and a number, are never equal.
- A date without a time, such as `2026-03-01`, covers that whole day in the viewer's time zone.
- `custom` is for a column with its own `filterFn`. On a column without one, a `custom` filter keeps every row. On a column with one, every other operator is left out and reported to `onError`.
